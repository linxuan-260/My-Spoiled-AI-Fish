# 架构

## 一句话

记忆系统**只往 `system_prompt` 里追加带唯一 marker 的注入块，从不修改人格本身**。所有增强都是可逆的：拿掉 marker，prompt 与注入前逐字节相同。

## 五层

| 层 | 管什么 | 典型产出 |
|---|---|---|
| L1 记忆 | 事实、经历、想法 | 「上个月说过退伍费的事」 |
| L2 情绪 | 当前心情与触发点 | 「今天有点闷，被那句玩笑戳到了」 |
| L3 生活 | 她正在做的事 | 「刚在阳台站了一会儿」 |
| L4 表达 | 语气、口头禅、长短句 | 「说话短，爱用反问」 |
| L5 反馈 | 表达效果的回流 | 调整 L4 的权重 |

`compose.run()` 按 L1→L4 依次构建，每层产出**带 marker 的文本块**，最后一次性拼接进 prompt。

## 注入流水线

```
on_llm_request
   └─ compose.run(prompt, ctx, cfg)
        ├─ markers.begin()            打上本次注入的边界
        ├─ l1_memory / l2_mood / l3_life / l4_style   各产出 block
        ├─ budget.fit()               超预算裁剪 / 丢弃
        ├─ markers.render(all_blocks) 一次性拼接（关键）
        └─ 断言：每层都能被 markers.extract() 找回，否则放弃本次注入
   └─ ledger.log()                   写 injection_ledger，事后可查
```

### 三个不能踩的坑

1. **`markers.render()` 必须一次性拼接。**
   历史 bug：它循环调用 `append_block()`，而每次 `append_block` 开头都 `strip_all()`，于是后一块把前面的块全抹掉 —— 账本记得四层都进了，prompt 里实际只有 style。表现就是「她根本记不住事」。
2. **单层超预算会被整块丢掉。**
   所以每层构建时自己按预算裁剪（`l3_life` 就是这么改的），而不是产出超预算块等上层丢。
3. **总量超预算要按重要度丢。**
   顺序是 style → life → mood → memory，保记忆。

## 记忆分两段：一直记着的 / 刚想起来的

L1 不是「每轮把检索结果贴进去」那么一件事：

| 段 | 来源 | 什么时候出现 | 怎么用 |
|---|---|---|---|
| 【一直记着的】 | `memories.tier='core'` | 每轮都在，与这句话说了什么无关 | 决定这轮怎么接话，不复述 |
| 【刚想起来的】 | 五路加权检索（`retrieve.py`） | 这句话命中才有 | 自然带一句，用完即弃 |

**为什么分**：检索是按这句话的关键词去查库，模型看到的是「查到几条记录」，于是照着念——这就是「翻旧账」。沉淀层换个位置、换个说法（「你本来就知道的事」），才是「记得」。

**谁进 core**：`daily_digest` 每晚跑 `memorydb.consolidate()`。

- 升：`kind` 属于 fact / reflection / lesson，且 `importance >= 0.6`，并且（`access_count >= 3` 或 `importance >= 0.7`）
- 降：已归档，或 120 天没被检索到（`last_access` 为空看创建时间）
- 封顶：总数最多 30 条，超了按「重要度、被想起次数」留最好的
- 沉淀层自己**不计** `access_count`，否则进了 core 就永远不下来

手工管理：`share_memory.py --core 42,43` / `--normal 42` / `--consolidate`；面板记忆表有「层次」列。

## 可见性

`memories.visibility` 三档：

| 值 | 谁能检索到 | 怎么产生 |
|---|---|---|
| `private` | 只有本会话 | 默认 |
| `owner` | 本会话 + `master.owner_id` 这个人的其它会话 | 一批消息只来自 owner 时自动打 |
| `public` | 共享层读者 | 面板点徽章 / `share_memory.py --public` |

共享层由两个配置决定：`public_scopes`（来源会话）和 `public_readers`（读者，留空=所有会话可读）。
同 hash 去重时**可见性只升不降**。

## 数据

```
data/plugin_data/astrbot_plugin_fish_memory/
├── memory/memory.db     记忆 + injection_ledger
├── emotion/emotion.db   情绪
├── life/life.db         活动 / 随笔 / daemon_state
├── style/style.db       表达风格
└── feedback/feedback.db 反馈
```

`injection_ledger` 是最有用的排障表：每次注入的层、命中的记忆 id、块字符数、总字符数。

## Worker

| 进程 | 干什么 | 默认节奏 |
|---|---|---|
| `ingest_worker` | 按会话分批把聊天记录提炼成记忆 | 持续轮询 |
| `life_daemon` | 生成生活活动 / 随笔，到点触发自主探索 | 20 分钟一拍 |
| `daily_digest` | 每日汇总 | 每天一次 |

## 自主探索

`worker/browser.py` 的 `maybe_browse()`：

```
LLM 出题（≤18 字，避开最近 8 条）
  → 搜索接口 search 取前 3 条
  → extract 取第一条正文
  → LLM 用她自己的语气写「看到了什么 + 我怎么判断」（≤55 字，带 keep 判断）
  → 写 life_notes（TTL 36h）；keep=true 再写记忆
```

默认 2 小时一次，状态存在 `life.db` 的 `daemon_state` 表（`last_browse` / `browse_history`）。

## 人格只读

`persona_guard` 只做两件事：定期对 `personas.system_prompt` 算 sha256 与基线比对、在面板上亮灯。
`enabled=false` 与 `auto_restore=false` 时**不会写回人格**。要让它有意义，基线必须与线上人格一致 —— 详见 [配置 · 人格校验](配置.md)。
