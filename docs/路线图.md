### 1. 真记忆，而不是每次翻旧账（已完成）

肥鱼自己在群里提的：「我想能记事儿，是真记，不是每次翻旧账那种。」

现状：每轮请求都从 SQLite 检索一遍、拼进 system prompt。对模型来说这更像「查档案」，而不是「想起来」。区别在于——真记得的东西会改变当下的反应，翻档案只会复述。

目标方向：区分「记忆」（长期沉淀、改变行为倾向）与「检索结果」（临时引用、用完即弃）。

### 2. 自己判断什么时候该闭嘴（已完成）

肥鱼自己在群里提的：「还想能自己判断什么时候该闭嘴。」

现状：`L3_life.llm_activity_prob = 0.35` 决定它有多大几率主动冒泡，但这是**概率**，不是**判断**。它没有「这条不适合接」的能力，只是掷骰子。

目标方向：发言前加一道判别——话题是否敏感、场合是否合适、上次发言隔了多久、有没有人在正经说事。

## v1.2（下一版）

### 3. 记忆分层 + 遗忘曲线

用户提的：「要那种模仿人脑的多层级。今天中午吃了啥，第二天就忘了；但我是学生、我要做某件事这种，记得长一点。要不然上下文很快就用尽了。」

现状：

| 项 | 当前值 |
|---|---|
| 存储 | 一张 `memories` 表，靠 `kind` 区分类型 |
| 自动归档 | 只有 `episode` 超过 90 天归档（`archive_old`，digest 每晚跑） |
| 其他 kind | `fact` / `skill` / `lesson` / `reflection` **永不归档** |
| 检索排序 | 时间衰减（`decay_halflife_days`） |
| 注入预算 | 总计 400 字，其中 memory 层 **138 字**，约 3~4 条 |

问题：琐事和重要信息**同权竞争那 138 字**。247 条里，「爹（群主）目前单身」和「主人是退伍军人」在检索时没有本质区别。

目标方向：

- 重要信息（身份、长期目标、关系）升层，几乎不衰减，且优先入选
- 琐事（今天吃了什么、随口一句话）次日就淡出，连归档都不必留
- 中间层（最近几天的事）带半衰期
- 最终目的：把有限的注入预算留给真正改变行为的记忆

### 4. 记忆系统的寿命（已实测）

2026-11-01 实测数据：

| 指标 | 数值 |
|---|---|
| 总条数 | 249（active 235 / archived 14） |
| 数据库 | 1.5 MB |
| 日增 | 约 25 条（10-31 是 27 条） |
| 注入账本 | 每天 400~800 次 |
| 插件数据总量 | 4.4 MB |
| 磁盘剩余 | 23 GB |

结论：**存储不是瓶颈**。按 25 条/天，一年约 9000 条、60 MB，23 GB 够用几百年。

真正的天花板是**注入预算**：每次只能塞 138 字进 memory 层，约 3~4 条。记忆越多，越难把「对的那条」塞进去。

所以这个系统的「寿命」不取决于硬盘，而取决于**分层与排序做得好不好**——这正是第 3 条要解决的。

### 5. 四层之间互通

用户提的：「5 个模块可不可以互通？我记得之前做过，但感觉没完全通。」

**做完的是跨会话共享，不是跨层互通。** 这是两回事：

| 方向 | 内容 | 现状 |
|---|---|---|
| 纵向（跨会话） | 同一条记忆在别的群/私聊可见 | ✅ 已做（`private` / `owner` / `public`） |
| 横向（跨层） | 一层的判断影响另一层 | ❌ 基本没做 |

现状结构：

```
        compose.py 只干一件事：把四层并排拼进 prompt
                        │
   ┌────────┬───────────┼───────────┬────────┐
 记忆层    情绪层      生活层      表达层
memory.db  mood.db    life.db    style.db
   └──── 各读各的库，谁也不看谁 ────┘
                        ↑
                   反馈层 feedback.db
              （只在检测到"纠正"时给记忆降权）
```

四层的 `build(ctx, cfg)` 签名完全一样，`ctx`（`TurnCtx`）里只有这一轮的基本信息——谁说的、说什么、群还是私聊。**没有任何一层把结果传给下一层。**

已有的两条线：

1. 反馈层 → 记忆层：纠正时 `importance` × 0.15 降权（`main.py:155-163`）
2. 表达层 → 反馈库：改写记录进 `styledb.log_feedback`

缺失导致的实际症状：

| 场景 | 应该发生但没发生 |
|---|---|
| 情绪层显示今天低落 | 记忆层照样捞出负面记忆，火上浇油 |
| 生活层写着"正在写作业" | 记忆检索不会优先想起学习相关的事 |
| 记忆里有"主人是退伍军人" | 表达层不知道该收敛还是照常贫嘴 |
| 用户在群里纠正她 | 只有记忆降权，情绪和生活层收不到信号 |

互通的三个层次：

| 层次 | 内容 | 现状 |
|---|---|---|
| 数据互通 | 同一条记忆跨会话可见 | ✅ 已做 |
| 信号互通 | 一层判断影响另一层评分 | ⚠️ 只有 feedback→memory |
| 推理互通 | 综合多层决定"这次该说什么" | ❌ 没做 |

目标方向（不重写架构，改成有顺序、有传参）：

```python
mood  = l2_mood.build(ctx, cfg)     # 先算心情
life  = l3_life.build(ctx, cfg)     # 再算当前状态
ctx.mood_score = mood.score         # 挂到 ctx 上
ctx.life_tags  = life.tags
mem   = l1_memory.build(ctx, cfg)   # 记忆层现在能看到心情和状态
style = l4_style.build(ctx, cfg)    # 表达层根据"对谁说话"调整
```

改动集中在三处：

1. `budget.py` 的 `TurnCtx` 增加 `mood_score` / `life_tags` 字段
2. `compose.py` 把四层从「并列执行」改成「链式执行」
3. `layers/l1_memory.py` 的检索评分增加两个系数（心情调节、当前状态加权）

风险可控：某层异常时其余层照常工作（`compose.build_blocks` 已有 per-layer try/except），只是少一个系数。

### 6. 上下文压缩的应对（背景，非本次任务）

DeepSeek 的对话上下文会被 AstrBot 自动压缩，而不是「用完就重开」：

```json
"overflow_strategy": "llm_compress",
"keep_recent_ratio": 0.15,
"fallback_max_tokens": 128000
```

压缩一次，早期原话变摘要；压缩两次，摘要的摘要。**这才是「记不住」的根源**，不是会话被重置。

所以重要信息不能寄托在对话历史里，必须落在 SQLite + 注入。第 3 条（分层）和第 5 条（互通）正是在加固这条路径。
