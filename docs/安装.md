# 安装

## 前置

| 项 | 版本 |
|---|---|
| AstrBot | 4.29.3（≥ 4.20 理论上可用） |
| Python | 3.12 |
| 操作系统 | Linux（systemd） |
| QQ 后端 | OneBot v11（如 SnowLuma / NapCat） |

## 最快路径：一条命令

前置只要 AstrBot 已装在 venv 里，然后：

```bash
sudo bash deploy/install.sh
```

它会装好插件、tools 和三个 systemd 单元，细节见 [deploy/README.md](../deploy/README.md)。下面是从零开始的手动步骤，想搞清楚每一步在做什么就看这里。

## 1. 放置插件

把 `plugins/` 下的两个目录拷到 AstrBot 的插件目录：

```bash
cp -r plugins/astrbot_plugin_fish_memory /opt/astrbot/data/plugins/
cp -r plugins/astrbot_plugin_qzone        /opt/astrbot/data/plugins/
```

重启一次 AstrBot，确认插件被加载：

```bash
journalctl -u astrbot --since '2 min ago' | grep -i "Loading plugin astrbot_plugin"
```

## 2. 写配置

复制示例并按自己的情况修改：

```bash
cp config/fish_memory.config.example.json \
   /opt/astrbot/data/config/astrbot_plugin_fish_memory_config.json
```

**必改的一项**：`master.owner_id` 填你自己的 QQ 号（字符串）。留空的话跨会话记忆不生效。

配置是**热重载**的：插件盯文件的 mtime，改完下一次请求就生效，不用重启。

## 3. 起面板与 worker

`tools/fishmem_workers.sh` 负责拉起三个常驻 worker（ingest / life / digest），面板是独立进程：

```bash
cp tools/fishmem_web.py tools/fishmem_web_ui.html tools/fishmem_starmap.html /opt/astrbot/tools/
mkdir -p /etc/fishmem
```

Systemd 单元示意（按实际路径调整）：

```ini
# /etc/systemd/system/fishmem-workers.service
[Unit]
Description=Fish Memory Workers
After=network.target

[Service]
Type=forking
ExecStart=/opt/astrbot/tools/fishmem_workers.sh start
ExecStop=/opt/astrbot/tools/fishmem_workers.sh stop
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```ini
# /etc/systemd/system/fishmem-panel.service
[Unit]
Description=Fish Memory Panel
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/astrbot
ExecStart=/opt/astrbot/.venv/bin/python /opt/astrbot/tools/fishmem_web.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now fishmem-workers fishmem-panel
systemctl restart astrbot
```

面板默认只监听 `127.0.0.1:6186`，对外的正确做法是 SSH 隧道，不要直接暴露公网：

```bash
ssh -N -L 16186:127.0.0.1:6186 user@your-server
```

## 4. 验证装好了

```bash
# 服务
systemctl is-active astrbot fishmem-panel fishmem-workers

# 面板
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:6186/

# 各层是否真的注入了（这行是关键）
/opt/astrbot/.venv/bin/python - <<'PY'
import sqlite3
db = '/opt/astrbot/data/plugin_data/astrbot_plugin_fish_memory/memory/memory.db'
c = sqlite3.connect(db)
print(c.execute("select layer, count(*) from injection_ledger group by layer").fetchall())
PY
```

期望四层都有记录：

```
[('life', 274), ('memory', 405), ('mood', 863), ('style', 863)]
```

如果只有 `style` 一行，说明你碰到的是历史 bug（注入块互相覆盖），确认用的是本仓库版本。

## 5. 首次要跑的一遍

```bash
# 入库：把已有聊天记录提炼成记忆（worker 会自动做，也可以先手动跑一次）
/opt/astrbot/.venv/bin/python -m worker.ingest_worker

# 生活层：先播一轮种子活动
/opt/astrbot/.venv/bin/python -m worker.life_daemon --once

# 自检
/opt/astrbot/.venv/bin/python -m worker.eval_runner
```

`eval_runner` 会打印一组 PASS/FAIL，包含「人格未被改动」「注入可逆」「四层齐全」等不变量。

## 常见安装问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 面板起不来，`Address already in use` | 上一个进程没退干净 | 等 40s 再起，或 `pkill -f fishmem_web` |
| 语音发不出去 | 缺 `edge_tts` | 装进 venv，并补 `requirements.txt` |
| 记忆一条都不入库 | worker 没起 / 分批阈值没到 | 看 `journalctl -u fishmem-workers` |
| 面板显示「人格被改动了」 | 校验基线没同步 | 见 [配置](配置.md#人格校验) |
