## 三、一次请求发生了什么

```
QQ 消息
  → AstrBot 组 prompt（最近上下文 + 人格）
  → on_llm_request(main.py:69)
      ├─ 构造 TurnCtx（scope_id / umo / user_text / sender_id / is_group / persona_id）
      ├─ compose.run(prompt, ctx, cfg)
      │     ├─ l1_memory.build()  检索记忆       → 138 字预算
      │     ├─ l2_mood.build()    当前情绪       → 72 字
      │     ├─ l3_life.build()    正在干嘛       → 110 字
      │     ├─ l4_style.build()   说话风格       → 130 字
      │     ├─ fit()              超预算整块丢弃（从尾部）
      │     └─ markers.render()   拼进 system_prompt
      ├─ 校验 strip_all(结果) == strip_all(原 prompt)，不等就放弃本次注入
      └─ 写 injection_ledger（layer / memory_ids / block_chars / total_chars / shadow）
  → 调模型
  → 回复
```

关键点：**四层是并列的**，没有任何一层读取另一层的输出。这是 v1.1.1 第 5 条要改的。

## 四、数据模型

| 库 | 路径（相对 `plugin_data/astrbot_plugin_fish_memory/`） |
|---|---|
| 记忆 | `memory/memory.db` → `memories`、`memories_fts`、`memories_edges` |
| 情绪 | `emotion/emotion.db` |
| 生活 | `life/life.db` |
| 表达 | `style/style.db` |
| 反馈 | `feedback/feedback.db` |

`memories` 关键列：`id, kind, text, text_norm, hash, category, importance, valence, arousal, dominance, created_at, last_access, access_count, status, visibility, scope_id, merged_into`

- `hash` 是 **UNIQUE**，等于 `sha256(kind + "\x00" + norm(text))`
- **改 `text` 必须同时更新 `text_norm` 和 `hash`**，否则唯一约束或去重会出问题
- 工具函数：`memorydb.make_hash(kind, text)`、`bigram.norm(text)`

可见性：`private`（本会话）/ `owner`（同一个人跨会话）/ `public`（共享层）。

## 五、v1.1.1 四项任务

### 1. 真记忆，不是翻旧账 —— 已实现（2026-11-01）

原来：每轮都从 SQLite 检索、拼 prompt，模型视角像「查档案」，于是照着念。

现在 `layers/l1_memory.py` 一次产出两段：

| 段 | 来源 | 什么时候出现 |
|---|---|---|
| 【一直记着的】 | `memories.tier='core'` | 每轮都在，与这句话说了什么无关 |
| 【刚想起来的】 | 五路检索（`retrieve.py`） | 这句话命中才有 |

- 沉淀：`memorydb.consolidate()`，`daily_digest` 每晚跑。升 core 要 `kind ∈ {fact, reflection, lesson}`、`importance >= 0.6`，并且（`access_count >= 3` 或 `importance >= 0.7`）；归档或 120 天没被检索到的降回 `normal`；总数封顶 30。沉淀层自己不计 `access_count`。
- 降温：同一条记忆 20 分钟内不再进「刚想起来的」（`L1_memory.repeat_cooldown_min`），治「隔两句就说同一件事」。
- 预算：memory 138→168、style 130→100（实测表达层恒定 46 字，额度用不上）。
- 手工：`share_memory.py --core 42,43` / `--normal 42` / `--consolidate`；面板记忆表按「层次」筛选。

### 2. 自己判断什么时候该闭嘴

现状：`L3_life.llm_activity_prob = 0.35` 是掷骰子，不是判断。

切入点：`worker/life_daemon.py` 的主动发言分支。需要在掷骰子之前加一层判别（话题敏感性、场合、上次发言间隔、是否有人在正经说事）。

### 3. 记忆分层 + 遗忘曲线

现状：

| 项 | 当前 |
|---|---|
| 自动归档 | 只有 `episode` 超 90 天归档（`memorydb.archive_old`，digest 每晚跑） |
| 其他 kind | `fact` / `skill` / `lesson` / `reflection` 永不归档 |
| 排序 | 时间衰减 `decay_halflife_days` |
| 预算 | memory 层 138 字，约 3~4 条 |

问题：琐事和重要事实同权竞争那 138 字。

切入点：`layers/l1_memory.py` 评分 + `store/retrieve.py` 排序。需要引入「层级」维度（核心/近期/琐碎），不同层级不同衰减和不同入选概率。

**注意**：改评分会立即影响全部 235 条 active 记忆的检索结果。建议先用 `shadow_mode` 观察。

### 4. 四层互通

现状见 [路线图](路线图.md) 第 5 条。四层各读各的库，只在 `compose.build_blocks` 里并排拼接。

切入点三处：

1. `budget.py` 的 `TurnCtx` 增加 `mood_score` / `life_tags`
2. `compose.py` 把 `LAYER_MODULES` 的并列 for 循环改成显式顺序：先 mood、再 life、再 memory、最后 style
3. `layers/l1_memory.py` 的评分加系数

**风险**：`compose.build_blocks` 有 per-layer try/except，某层抛异常只会丢那一块。改成链式后要保证前一层失败不阻塞后一层。

## 六、必须知道的坑

1. **注入必须可逆**。`markers.strip_all(注入后) == markers.strip_all(注入前)` 不成立时，`compose.run` 会放弃本次注入并返回原 prompt。这是设计上的人为约束，不要绕过。

2. **`markers.render()` 只能整体渲染一次**。历史 bug：按块分别渲染，结果只注入了最后一块（11-01 修复）。加新层时容易再犯。

3. **改 `memories.text` 要连带改两列**（`text_norm`、`hash`），见第四节。

4. **人格是只读的**。`persona_guard` 会校验哈希，任何直接写人格文件的行为都会触发红灯。要改人格走人工流程。

5. **预算总计 400 字**。加内容前先看 `injection_ledger.total_chars` 的实际分布，别把某一层挤没。

6. **配置热重载**：JSON 改完立刻生效（按 mtime）。改 `.py` 必须重启对应服务，见下表。

7. **重启边界**：

   | 改了什么 | 重启什么 |
   |---|---|
   | `plugins/*.py` | `astrbot` |
   | `worker/*.py` | `fishmem-workers` |
   | `tools/fishmem_web.py` | `fishmem-panel` |
   | 配置文件 | 什么都不用重启 |

8. **本地 Windows 的环境问题**（这台机器特有）：

   - 没有装 Git for Windows，`git` 只在 DSH 沙箱里
   - HTTPS 到 GitHub 会报 `CRYPT_E_NO_REVOCATION_CHECK`，需要 `git -c http.sslVerify=false`
   - 私钥文件权限必须是「仅当前用户」，否则 Windows ssh 拒绝加载

9. **服务器所有服务只绑 `127.0.0.1`**，必须走 SSH 隧道访问面板。

## 七、验证方法

**四层是否都在注入**（唯一可信的检查）：

```bash
sqlite3 memory/memory.db "select layer,count(*) from injection_ledger group by layer"
```

四层都有数字才算正常。

**最近一次注入长什么样**：

```bash
sqlite3 memory/memory.db "select ts,layer,memory_ids,block_chars,total_chars from injection_ledger order by id desc limit 8"
```

**沉淀层（一直记着的事）现在有哪些**：

```bash
/opt/astrbot/.venv/bin/python share_memory.py --stats          # 层次分布
/opt/astrbot/.venv/bin/python share_memory.py --list --limit 20 | grep core
```

`memory` 层的 `block_chars` 应从 ~100 涨到 ~150（多了一段）；`share_memory.py --stats` 里 `core` 那行应该有十几到三十条。

**单元测试**：

```bash
cd /opt/astrbot && .venv/bin/python -m pytest data/plugins/astrbot_plugin_fish_memory/tests -q
```

**灰度**：把 `shadow_mode` 设为 `true`，注入照常计算并记账，但不真的写进 prompt。适合调评分时观察。

**面板 / 星图**：经隧道访问，本轮记忆的注入情况、图谱、健康度都在上面。
